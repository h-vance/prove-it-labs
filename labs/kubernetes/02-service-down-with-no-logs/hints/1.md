The customer thinks the missing logs are the mystery. They are actually the
best clue in the ticket, and saying so will change how they see the incident.

Work through what an empty log rules out. If the application had started and
then failed, it would almost certainly have said something first: a stack
trace, a connection error, a validation message. Nothing at all means your code
was probably never reached.

That splits the world cleanly. Everything that happens before the process runs
is still in play, and everything the application itself does is not.

So the question is no longer "what went wrong in the service". It is:

> What has to succeed before the process is allowed to start?
